# 计算器截图缺陷修复与补验

前一轮验收检查了场景状态和计算逻辑，遗漏了计算器的刻度布局、页面展示的观测来源及供数前提。不能以原有自动测试通过代替这些界面的验收。

复现：已暂停的6条输入，保留时间观测7份／10.8秒，但没有冻结成本样本。打开计算器，选择按时长并填818分钟。修复前显示成本样本0份、时间结果31,811份／0.00小时，分钟刻度仍为0、8、24并互相重叠。

修复：

- 按当前试算分别展示成本和时间依据。成本样本不足不再被当作总成品为零；独立时间观测仍可提供时间试算。
- 短时间显示秒；正观测时长不舍入成0.00小时。
- 滑杆标签均匀覆盖实际量程，跟随单位和数值范围变化。分钟、小时、天切换保留同一时长；最大预算和目标数字完整显示。
- 有供数前提的外推标为预计产能，在结果旁显示输入供给状态。
- 明确结束且没有输入、在途或重试任务时，当前输入可新增0份；正数交付目标没有可完成的时间或费用估算。开放供数等待新增时仍可条件试算；不按原始输入数截断一对多成品数。

补验：125项自动测试、lint、类型检查、静态构建和公开内容检查通过。浏览器回归检查818和43,200分钟、720小时、30天、10万元预算、10万份目标，窗口宽1440／1024／800，以及缺少成本样本、输入结束与正目标阻断。新测试先观察到失败，再验证修复；详见browser-report.json和截图。

运行浏览器补验时可设置PLAYWRIGHT_MODULE、DEMO_URL、REPORT_DIR；不操作用户原浏览器的数据。
