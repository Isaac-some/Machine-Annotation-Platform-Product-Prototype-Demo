# 演示入口与固定CID验收 · 2026-11-11

[公开原型](https://isaac-some.github.io/Machine-Annotation-Platform-Product-Prototype-Demo/) · [E1 PRD](https://fyze31atzb.feishu.cn/docx/GijVd2PMmoqERgx9nGPc5Cpsnkb) · [云端验收](https://fyze31atzb.feishu.cn/docx/WxdVdbmIeoNurGxUuvkcPHn0nOg)

首页恢复项目管理平台原界面。所有平台页面左下提供52px圆球，打开左侧演示抽屉；选择后准备合成数据并跳转，停在“待开始演示”；手动点“开始演示”才推进。CSV读取也须手动开始。正式PRD已在36项功能说明旁补充直达链接，映射见 [链接清单](prd-demo-links.json)。

| 场景 | 固定输入CID | 预置条件 |
|---|---|---|
|实际成本上限|CID://demo-cost-limit|预热550步并完成预置积压，当前费用加0.20元为上限|
|实际处理时长上限|CID://demo-time-limit|已累计处理时间加2.4秒为上限，等待与暂停不计入|
|最终成品目标|CID://demo-output-limit|已有最终产物加2份为目标|
|原始输入条数上限|CID://demo-input-limit|已取入原始数据加3条为上限|

每个场景只开启对应边界，选择后停住，等待和刷新均不自行运行；10秒从手动点“开始演示”计起，覆盖达限、停止新增、完整收尾，完成后费用稳定。最终成品目标保留既定重试规则。提高限制并保存不会自动继续，仍需人工继续。场景复用专属批次并暂停其他模拟任务，重复演示不会增加历史批次。

`demo=场景`负责准备，完成后从地址移除以便刷新保留；`panel`打开配置、累计详情、计算器、克隆、交付、批次只读配置、告警或失败详情。批次失败直达根据演示执行器当前批次选择第二环节，避免写死动态编号。合成失败同步到失败明细，重试所选环节会清除该环节记录；没有真实算子追踪时明确无法定位。

## 验证

128项主应用测试、lint、类型检查、生产静态构建通过。生产静态文件的自动化验证包括首页圆球位置、三种CID边界、4个执行器窗口、3个批次窗口、全新浏览器存储直达计算器和失败详情。结果见 [静态浏览器记录](static-browser-check.txt)。以下旧截图保留追溯。新版真实可见Chrome窗口另通过系统辅助功能点击并截图，画面只裁切浏览器外框，未修改界面内容。

## 手动开始与成本完整收尾修复

旧版550步预热时积累了113个在途任务，实际要约139秒才能收尾完；仅验证触顶信号不足以确认演示全程。新版先沿真实模拟路径结清预置积压，再设置临界上限，手动开始后只处理少量新数据。停止新增和在途费用规则保持原义。

顶部显示“待开始演示→运行中→收尾中→等待人工决定”。收尾时明确展示固定的已取入条数和仍在途的原始输入数量；最终在途归零，费用稳定。已有触顶信号时隐藏旧的“提前提醒不会暂停”文案，运行详情也不再把收尾和等待标成自动连续。
