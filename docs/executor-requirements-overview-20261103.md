# 执行器与批次能力：需求总览

需求仍由两份详稿承载：执行器二期解决持续产出和成品成本决策，批次共用能力解决失败恢复、值守提醒和阶段性交付。2026-11-04 用户已确认直接启动、持续估算与独立成本上限、有限重试与人工补救、可选目标量停取入；时间→产量确认为低优先级必做需求。2026-11-05 用户进一步确认实际成本触顶可选择停止新增并收尾，或按配置强度提醒后继续；预测费用不阻断生产。成本梯度提醒列为低优先级后续需求。原型整体无重大问题，并需整理配置可读性及演示数据匿名化。这些决定覆盖此前冲突规则。总览只负责导航、范围与依赖，不维护第三套细则。

## 本次统一后的关键边界

- 整批保留默认／严谨／目标；流式独立策略。首次启动锁定输入、运行方式与链路。
- 固定输入；可读成功结果及时下传，支持拆分。首次启动后输入和链路锁定。
- **2026-11-04 已确认**：流式配置完成后直接开跑，不设置样本跑完和人工确认预算的启动闸门；观察批量仅控制估算窗口。
- **2026-11-04 已确认、2026-11-05 补充**：按已收尾输入持续估算成本与可交付产量；预测费用不阻断生产或重试。实际费用达到独立可选成本上限后，用户可选停止新增输入和自动重试、在途任务继续收尾（最终费用允许超限），或仅按成本上限通知强度提醒并继续生产及有限重试。触顶提醒强度不低于全局通知基准。
- 成本样本来自已收尾输入及其费用、最终成品配对；样本不足、缺失或零成品时说明原因，不声称统计置信度或生产费用保证。
- 输入条数、累计处理时长等设置在当前界面可选。**2026-11-04 已确认**：目标成品量是可选停取入上限；留空不按目标停机，达到已填目标后停止新增输入，在途继续收尾，失败数据仍按配置次数自动重试，最终成品数可能超出目标；成本和时长等其他运行上限继续生效。
- **2026-11-04 已确认**：时间→产量纳入后续开发，标为 P2 低优先级必做；有有效吞吐数据时按投入时长估算新增可交付产量，数据不足时说明不可估算原因。当前原型只有不可估算提示，实际预测仍待实现。
- **2026-11-04 已确认**：自动重试限定次数，保留暂停后的人工失败数据补救；本轮不要求以全链成本收益预测作为自动重试门槛。生产输入扫描、幂等与资源成本仍待联调。
- **2026-11-05 界面验收反馈**：整体无重大问题；成本控制、运行时长、输入/成品目标及失败重试应分组显示，并用线性图标辅助识别。只调整界面层级，不改变已确认的业务行为。
- **2026-11-05 演示数据匿名化**：演示工作流及项目名称使用三国故事相关词语，人员字段使用《三国演义》人物名；不得出现真实人员姓名。仅作用于演示样例，不改变生产账户身份。
- **2026-11-05 成本字段确认**：移除不参与预测的“单条成品成本预估上下限”；成本估算继续依据已收尾样本持续更新，不另设单条成本覆盖值。历史保存值仅为兼容数据，不读取为估算规则。
- 重叠范围完整导出，失败重试原任务原快照。主动导出不驱动下游；整批等收尾文件，流式消费就绪结果。
- 必要关联先做，完整逐条与跨平台追溯后置。克隆展开需求并独立排期，配置复用与运行结果隔离。
