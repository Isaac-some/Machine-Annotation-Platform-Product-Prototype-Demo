# 执行器录屏迭代与验收

以飞书原文档为正式PRD；本目录保存当前交互截图与验证证据，均为合成数据原型，未连接生产存储或计费服务。

- 原始数据输入与最终成品分别配置。输入量按原始条数，目标按最终成功产物份数；允许一对多。
- 首次估算为初始输入量的5%，最多1,000条；增量为2%，最多400条；条数向上取整且最少1条。未知总量采用500／200条。后续补量不抬高本轮基准。运行详情可手动刷新，样本不足不伪造结果。
- 运行和试算时长支持分钟；实际处理时长排除暂停、等待、排队，并行只计一次。
- 右下角“演示与验收”准备固定场景，复用同一组批次，自动暂停其他本地模拟任务。550步成本场景分段准备，保持界面响应。
- CSV演示先模拟读取与RowKey校验，再显示总量；缺少RowKey不处理数据。仅模拟已知测试输入，不代表连接任意真实CSV解析服务。
- 原型最多模拟10,000条输入，大数值在进入计算前拒绝；200万条的采样规则用数学边界测试，不生成200万条浏览器结果。该限制不代表生产容量。

演示输入在 `public/demo/executor/`：240条有效CSV、6条等待补量CSV、1,000条成本演示CSV，以及缺少RowKey的反例。TOS路径为合成标识，对应文件不包含真实媒体。

验证：`npm test`、`npm run check`、`npm run audit:public`；编辑器测试、lint及类型检查。浏览器证据见 `browser-report.json`、`scenarios-browser-report.json`。
